## 修复：双击节点内联编辑失效
- 现象：双击节点无法编辑（`onEdit` 不触发），但 F2 / 右键能编辑。
- 根因：`render.js` 节点 click 处理器调用 `draw()` 整树重绘，重建了节点 `<g>`；双击需"同一元素两次点击"，元素被重建导致浏览器不派发 `dblclick`。
- 修复：选中改为轻量更新 `applySelection()`（仅切换 class + 增删虚线框，不重绘整树），节点元素身份保持 → 双击可触发 → `startInlineEdit` 在节点上覆盖 textarea 编辑。draw() 末尾统一调用 applySelection 还原选中态。
- 测试：test/render-smoke.js 新增 `select-persist` 断言（选中后节点 `<g>` 身份不变且挂 selected 类），`npm test` 全绿。

## 修复：单击/双击节点直接在节点上编辑
- 用户诉求：无论单击还是双击，都应直接在节点上编辑文本。原逻辑单击只选中、双击才编辑，且 `clientRectOf` 用手动坐标换算（布局坐标×缩放），`fit()` 缩放后编辑框易偏到屏幕外/错位 → 看似"不能编辑"。
- 修复：
  1) `render.js` 节点 `click` 改为"先 `select` 再直接 `startInlineEdit`"——单击即编辑；`dblclick` 仅 stopPropagation（双击第二次点击落在已弹出的 textarea 上，复用同一编辑框、不抖动/重开）。
  2) `clientRectOf` 改用节点真实 DOM 矩形（`viewport.querySelector('.node[data-id]')` 取 `<g>`，再用首个 `rect` 的 `getBoundingClientRect()`）——无论缩放/平移/手绘旋转都精准覆盖节点。
  3) `startInlineEdit` 加去重（`dataset.nodeId` 相同则跳过）、`setTimeout(0)` 后聚焦、输入即同步 model（不重绘避免打断）。
- 测试：test/render-smoke.js 新增 `click-to-edit` 断言（模拟节点 click → `onEdit` 回调被触发 1 次），`npm test` 全绿（clickEditTriggered=true）。

## 修复：缩放手柄拖不动（bug）
- 现象：选中节点后右下角手柄无法拖拽（"缩放拖不动"）。
- 根因：① 手柄原定位在**节点框内**右下角；而单击节点即弹出内联编辑 textarea（z-index 1200，覆盖整个节点），它位于 SVG 之上、会拦截手柄的 mousedown，导致手柄永远抓不到。② 编辑器在选中后保持打开，进一步挡住手柄。
- 修复（`render.js`）：
  1) `makeHandle` 把手柄移到节点右下角**外侧**（`x:n._w-3, y:n._h-3`，HANDLE=14，带白描边）——露出在节点框外，编辑器（仅覆盖节点矩形 [0..w]）不再压住它，手柄可抓取。
  2) `startResize` 开头先 `blur()`+`remove()` 掉已打开的内联编辑器，彻底排除拦截；手柄自身的 click 仍 stopPropagation，避免误触发编辑。
  3) `redrawSingleNode` 在拖拽实时重绘后，若该节点仍选中则重新挂上虚线框+手柄，避免重绘中选中态"消失"。
- 验证：`node --check render.js` 通过；`npm test` 全绿（exit=0）。GUI 实机拖拽需本机 `npm start` 确认。

## 修复：缩放拖不动（真正根因 = Model.find 返回包装对象）
- ⚠️ 上一轮把"编辑器遮挡"当作主因是误判；加 `[FMM]` 调试 log 后用户实测日志暴露真正根因。
- 日志现象：`applySelection: handle ATTACHED <id> nodeBox= undefinedxundefined`、`makeHandle undefined x= NaN y= NaN`、`startResize ENTER undefined ... startW= undefined`、`resize move ... w= NaN`、以及大量 `<rect> attribute width: Expected length, "NaN"`。
- **真正根因**：`Model.find(map, id)` 返回的是**包装对象 `{ node, parent }`**，而 `render.js` 的 `applySelection` 与 `centerOn` 把返回值当成节点本身直接用（`n._w`/`n._h`/`n.id` 均为 undefined）→ 手柄坐标 NaN（不可见/抓不到）、拖拽数学全 NaN、选中虚线框也 NaN。
- 修复（`render.js`）：
  1) `applySelection` 与 `centerOn` 中改为 `const found = Model.find(state.map, id); const n = found && found.node;`（取真实节点）。
  2) 经此修复，日志变为 `nodeBox= 84x38`（有效尺寸）、`handle ATTACHED` 坐标有效；拖拽 `resize move / onUp finalW/finalH` 均为真实数值。
- 配合上轮改进（手柄移到节点框外侧 + 拖拽时关闭内联编辑器）共同生效。
- 附带：调试用的 `requestAnimationFrame` 测量手柄屏幕坐标需 `typeof requestAnimationFrame === 'function'` 守卫，否则 Node 测试垫片无 rAF 会抛错（`npm test` 一度报 select-persist/click-to-edit 失败，已修复）。
- 验证：`npm test` 全绿（exit=0，含 selectPersist/clickEditTriggered/userWidthOk）。调试 log 仍保留（`const DBG=true`），待用户本机 `npm start` 确认手感后可关闭。GUI 实机需本机确认。
