## 修复：双击节点内联编辑失效
- 现象：双击节点无法编辑（`onEdit` 不触发），但 F2 / 右键能编辑。
- 根因：`render.js` 节点 click 处理器调用 `draw()` 整树重绘，重建了节点 `<g>`；双击需"同一元素两次点击"，元素被重建导致浏览器不派发 `dblclick`。
- 修复：选中改为轻量更新 `applySelection()`（仅切换 class + 增删虚线框，不重绘整树），节点元素身份保持 → 双击可触发 → `startInlineEdit` 在节点上覆盖 textarea 编辑。draw() 末尾统一调用 applySelection 还原选中态。
- 测试：test/render-smoke.js 新增 `select-persist` 断言（选中后节点 `<g>` 身份不变且挂 selected 类），`npm test` 全绿。

## 修复：单击/双击节点直接在节点上编辑
- 用户诉求：无论单击还是双击，都应直接在节点上编辑文本。原逻辑单击只选中、双击才编辑，且 `clientRectOf` 用手动坐标换算（布局坐标×缩放），`fit()` 缩放后编辑框易偏到屏幕外/错位 → 看似"不能编辑"。
- 修复：
  1) `render.js` 节点 `click` 改为"先 `select` 再直接 `startInlineEdit`"——单击即编辑；`dblclick` 仅 stopPropagation（双击第二次点击落在已弹出的 textarea 上，复用同一编辑框、不抖动/重开）。
  2) `clientRectOf` 改用节点真实 DOM 矩形（`viewport.querySelector('.node[data-id]')` 取 `<g>`，再用首个 `rect` 的 `getBoundingClientRect()`）——无论缩放/平移/手绘旋转都精准覆盖节点。
  3) `startInlineEdit` 加去重（`dataset.nodeId` 相同则跳过）、`setTimeout(0)` 后聚焦、输入即同步 model（不重绘避免打断）。
- 测试：test/render-smoke.js 新增 `click-to-edit` 断言（模拟节点 click → `onEdit` 回调被触发 1 次），`npm test` 全绿（clickEditTriggered=true）。

## 需求：上排工具栏改为二级菜单（菜单栏）
- 用户要把平铺的工具栏分门别类收起，做成二级菜单。
- 分类：文件（新建/打开/保存/另存为）、节点（添加子/同级/折叠/删除）、视图（结构/方向/主题下拉 + 缩放行）、工具（大纲/搜索/演示）、导出（PNG/SVG/MD/PDF）。
- 实现：`index.html` 工具栏改为 `.menu > .menu-title + .submenu` 结构，**保留全部原 id**（btn-* / sel-* / zoom-*），故 `app.js` wireToolbar 按 id 的绑定逻辑零改动。
- 交互（`app.js` 新增 `wireMenus`）：点击 `.menu-title` 展开对应二级菜单并收起其他；执行命令项后收起；点击菜单栏外部关闭。另新增 `updateZoom()` 在缩放后刷新百分比显示（`Render.getState().view.k`）。
- 样式（`style.css`）：`.menu/.menu-title/.submenu` 及 `#toolbar .submenu button/select/sub-row/.kbd` 等，用 `#toolbar .submenu` 高特异性前缀覆盖原 `#toolbar button/select` 规则。
- 验证：`node --check app.js` 通过；`npm test` 全绿（exit=0）；Grep 确认 22 个原控件 id 全部保留。GUI 实机交互需本机 `npm start` 确认（沙箱限制）。

## 需求：删除渲染层 HTML 菜单栏，仅保留系统顶部菜单
- 用户反馈：render 里的菜单栏与系统顶上菜单栏"重了"（重复），只要系统菜单，把 render 的菜单合并进系统。
- 方案：
  1) `renderer/index.html` 删除 `<header id="toolbar">` 整段；状态栏新增 `#status-zoom` 显示缩放百分比。
  2) `renderer/css/style.css` 删除工具栏/二级菜单全部样式；`#stage` 高度改为 `calc(100vh - 28px)`（仅剩状态栏）；搜索/大纲面板 `top` 由 64px 改为 12px；新增 `#status-zoom` 样式。
  3) `main.js` 重构 `buildMenu()`：`menuState`(structure/direction/theme/themes) + `rebuildMenu()` + `setStructure/setDirection/setTheme`；新增「节点」菜单（添加子/同级/折叠/删除）与「视图→结构/方向」单选子菜单、「视图→适应窗口(Ctrl+9)」；「主题」子菜单由 `menuState.themes` 动态生成单选；原有文件/编辑/帮助/导出/缩放保留。新增 `ipcMain.on('menu:sync')` 接收渲染层状态回写并 rebuild。
  4) `preload.js` 新增 `window.mm.syncMenu(state)`（`ipcRenderer.send('menu:sync', state)`）。
  5) `renderer/js/app.js`：删除 `wireToolbar`/`wireMenus`（及调用）；`Render.init` 加 `onView` 回调 → `updateZoom` 写 `#status-zoom`；`init`/`newMap`/`openMap` 解构后调用新增 `syncMenu()` 回写状态；`handleMenuAction` 扩展 `add-child/add-sibling/collapse/delete/zoom-fit` 与 `structure:/direction:/theme:` 分支；`wireKeyboard` 移除 Ctrl+N/O/S/F（改由系统菜单加速器独占，避免重复触发）。
  6) `renderer/js/render.js`：`zoomAt/fit/resetView` 末尾调用 `state.callbacks.onView(k)`，使滚轮缩放也实时刷新状态栏百分比。
- 关键细节：系统菜单的 Tab/Enter/Del 加速器会"全局触发"，编辑节点文本按 Enter 时会同时触发"添加同级"→ 冲突。已**不挂加速器**（仅标签提示如"添加子节点 (Tab)"），键盘快捷键交由渲染层 `wireKeyboard` 在非输入态处理（isTyping 守卫）。
- 验证：`node --check` 全过；Grep 确认 app.js 已无 `sel-*`/`btn-*`/`wireToolbar`/`wireMenus`/`theme-` 残留引用；`npm test` 全绿（exit=0）。GUI 实机需本机 `npm start` 确认。
